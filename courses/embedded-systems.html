MODULE 1

GPIO Output & Blink Timing

A digital output pin is just HIGH or LOW. Toggling it with on/off delays makes a square wave — the classic "blink". The on/off times set the frequency and duty cycle.

💡 Try: equal ON/OFF → 50% duty square wave. Make ON ≫ OFF → mostly-on with a brief blink off.
Theory

For a period \(T = t_{on}+t_{off}\):

\[ f = \frac{1}{T},\qquad \text{Duty} = \frac{t_{on}}{t_{on}+t_{off}}\times100\% \]

In firmware this is a while loop with digitalWrite(HIGH); delay(t_on); digitalWrite(LOW); delay(t_off); — but using delay() blocks the CPU. Real designs use a timer (Module 3) instead.

MODULE 2

PWM & Duty Cycle

Pulse-Width Modulation switches a pin fast and varies the fraction of time it is ON. The load sees the average voltage — so PWM dims LEDs, sets motor speed, and synthesises analog levels from a digital pin.

LED brightness
pinaverage V
💡 Try: 25% → dim, 75% → bright. Note the average-voltage line (gold) tracks the duty cycle, independent of frequency.
Theory

With supply \(V_{cc}\) and duty \(D\), the average output voltage is

\[ V_{avg} = D\cdot V_{cc} \]

A low-pass filter (or the inertia of a motor / persistence of vision of an LED) extracts this average. Higher PWM frequency → easier to filter, smoother result. The resolution of the duty cycle is set by the timer (e.g. 8-bit PWM = 256 steps).

MODULE 3

Timer / Counter & Prescaler

Timers count clock ticks. A prescaler divides the system clock down, and the auto-reload (ARR) value sets how many ticks before the timer resets — together they generate precise time bases & interrupt rates without blocking the CPU.

💡 Try: 16 MHz, prescaler 16, ARR 999 → exactly 1 kHz (1 ms tick). Halve the clock → halve the rate.
Theory

The timer overflow (update) frequency is

\[ f_{timer} = \frac{f_{clk}}{\text{Prescaler}\times(\text{ARR}+1)} \]

The +1 is because the counter includes 0. On overflow the timer can fire an interrupt or toggle a pin in hardware — so timing is exact and the CPU stays free for other work (unlike delay()).

MODULE 4

ADC — Sampling & Quantization

An Analog-to-Digital Converter measures a voltage and maps it to an integer code. With \(n\) bits there are \(2^n\) levels — more bits means finer steps. The smooth analog signal becomes a staircase; the step size is the quantization error.

analogquantized
💡 Try: 2 bits → coarse 4-level staircase. 12 bits → nearly perfect (4096 levels). Raise samples/period to see finer time sampling.
Theory

The smallest voltage the ADC can resolve (1 LSB) is

\[ \text{LSB} = \frac{V_{ref}}{2^{\,n}},\qquad \text{code} = \left\lfloor \frac{V_{in}}{\text{LSB}} \right\rceil,\ \ 0\le\text{code}\le 2^n-1 \]
  • More bits → smaller LSB → less quantization error (but more data).
  • Sampling rate must satisfy Nyquist: \(f_s > 2 f_{max}\), or aliasing corrupts the signal.
MODULE 5

UART Serial Frame

UART sends a byte one bit at a time over a single line: an idle-high line, a start bit (low), 8 data bits (LSB first), an optional parity bit, then stop bit(s). Both ends must agree on the baud rate (bits/second).

💡 Try: byte 65 = 'A' = 0b01000001 (sent LSB-first). Switch parity to Even and watch the parity bit appear before the stop bit.
Theory

Each bit lasts \(t_{bit} = 1/\text{baud}\). A 10-bit frame (1 start + 8 data + 1 stop) at 115200 baud takes \(\approx 86.8\,\mu s\).

\[ t_{frame} = (1 + n_{data} + n_{parity} + n_{stop})\times\frac{1}{\text{baud}} \]
  • Data is sent LSB first.
  • Even parity: parity bit makes the total number of 1s even; odd: makes it odd. It catches single-bit errors.
  • UART is asynchronous — no clock line — so a baud mismatch > ~2-3% garbles the data.
MODULE 6

Switch Debouncing

A mechanical switch doesn't close cleanly — the contacts bounce for a few milliseconds, producing many fake edges. Debouncing waits until the signal is stable for a set time before accepting the new state, so one press = one event.

raw inputdebounced
💡 Try: set debounce time below the bounce duration → glitches leak through (multiple events). Set it above → one clean edge.
Theory

The debounce rule: only accept a new level after the input has held that level continuously for \(t_{debounce}\). Choose \(t_{debounce}\) larger than the worst-case bounce (typically 5–20 ms).

  • Software: sample periodically; reset a timer on every change; commit when the timer exceeds \(t_{debounce}\).
  • Hardware: an RC filter + Schmitt trigger, or an SR latch with a SPDT switch.
